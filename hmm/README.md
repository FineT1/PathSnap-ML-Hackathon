# PathSnap – Member 3: Hidden Markov Model (HMM) & Viterbi Route Reconstruction

## 1. What is a Hidden Markov Model (HMM)?

A **Hidden Markov Model (HMM)** is a statistical framework for modeling sequences where the true underlying states of interest are **hidden** (unobservable directly) and can only be inferred through noisy, probabilistic **observations**.

An HMM is defined by the tuple $\lambda = (S, O, \Pi, A, B)$:
* $S = \{s_1, s_2, \dots, s_K\}$: Set of possible hidden states.
* $O = (o_1, o_2, \dots, o_T)$: Sequence of observed measurements across time steps $t = 0, 1, \dots, T-1$.
* $\Pi = \{\pi_i\}$: Initial state probability distribution where $\pi_i = P(s_0 = i)$.
* $A = \{a_{ij}\}$: State transition probability matrix where $a_{ij} = P(s_t = j \mid s_{t-1} = i)$.
* $B = \{b_j(o_t)\}$: Emission probability distribution where $b_j(o_t) = P(o_t \mid s_t = j)$.

Markov Assumption:
1. First-order Markov property: The current hidden state $s_t$ depends only on the immediately preceding hidden state $s_{t-1}$, i.e., $P(s_t \mid s_{t-1}, s_{t-2}, \dots, s_0) = P(s_t \mid s_{t-1})$.
2. Conditional independence of observations: The observation $o_t$ depends only on the current hidden state $s_t$, i.e., $P(o_t \mid s_t, o_{t-1}, \dots, o_0) = P(o_t \mid s_t)$.

---

## 2. Why is HMM Useful for GPS Map Matching?

Raw GPS traces collected from vehicle tracking devices suffer from significant errors due to:
* Ionospheric signal delay and clock drift.
* Multi-path reflections (multipath interference from tall buildings or urban canyons).
* Sparseness of measurement intervals (e.g. 5–30 second sampling gaps).

If one simply maps each GPS point to the nearest road segment (the naive "Classifier-Only" or "Nearest Arc" approach):
* The vehicle appears to jump randomly between parallel access roads, highway lanes, overpasses, and cross streets.
* Consecutive selected road segments violate physical road network topology and traffic rules (e.g. illegal U-turns, wrong-way travel on one-way streets, or non-contiguous teleportations).

HMM solves this by balancing two competing signals simultaneously:
1. **Geometric/ML fit (Emission)**: How close and plausible is candidate arc $c_i$ to GPS point $o_t$?
2. **Topological plausibility (Transition)**: Can the vehicle actually drive from arc $c_{t-1, i}$ to arc $c_{t, j}$ along the directed road network in the elapsed time $\Delta t$?

---

## 3. What are Hidden States?

In PathSnap:
* For each GPS observation $t$, the candidate road segments $C_t = \{c_{t, 1}, c_{t, 2}, \dots, c_{t, K_t}\}$ generated by Member 1's candidate generator within search radius $R$ form the **discrete hidden state space** at time $t$.
* Each state $s_t$ corresponds to a unique directed road arc ID in the road network graph.

---

## 4. What are Observations?

The observation sequence $O = (o_0, o_1, \dots, o_{T-1})$ consists of the chronological sequence of GPS fixes:
$$o_t = (\text{lon}_t, \text{lat}_t, \text{timestamp}_t, \text{speed}_t, \text{heading}_t)$$
where timestamps are in seconds and coordinates are mapped to metric Cartesian coordinates using EPSG:27700 (British National Grid).

---

## 5. How are Emission Probabilities Calculated?

The emission probability $P(o_t \mid s_t = c_{t, i})$ measures how likely GPS fix $o_t$ is observed if the vehicle were truly traversing candidate road arc $c_{t, i}$.

### A. Geometric Observation Likelihood (Gaussian Noise)
Following Newson & Krumm (2009):
$$P_{\text{geom}}(o_t \mid c_{t, i}) = \frac{1}{\sqrt{2\pi}\sigma_z} \exp\left( - \frac{d(o_t, c_{t, i})^2}{2\sigma_z^2} \right)$$
where:
* $d(o_t, c_{t, i})$ is the perpendicular distance in metres from the GPS point to the road arc segment.
* $\sigma_z$ is the standard deviation of GPS measurement error (default $\sigma_z = 20.0$ m).

### B. Machine Learning-Informed Emission
Member 2 trains 5 supervised models predicting candidate match likelihood:
$$P_{\text{ML}}(s_t = c_{t, i} \mid o_t) = P(y = 1 \mid \mathbf{x}_{t, i})$$
where $\mathbf{x}_{t, i}$ includes `distance_m`, `dist_rank`, `dist_gap_m`, `bearing_diff_deg`, `speed_mps`, `time_gap_s`, and `segment_length_m`.

### C. Hybrid Combined Emission Formulation (Default)
In log-space:
$$\log P_{\text{emit}}(c_{t, i}) = (1 - \alpha) \log P_{\text{ML}}(c_{t, i}) + \alpha \log P_{\text{geom}}(c_{t, i})$$
where $\alpha \in [0, 1]$ (default $\alpha = 0.2$).
Probabilities are clipped to $[\epsilon, 1.0 - \epsilon]$ ($\epsilon = 10^{-12}$) to prevent numerical underflow.

## 7. How are Transition Probabilities Calculated?

The transition probability $P(s_t = c_{t, j} \mid s_{t-1} = c_{t-1, i})$ models the probability of moving from candidate arc $c_{t-1, i}$ to candidate arc $c_{t, j}$.

### Formulation:
Let:
* $d_{\text{obs}} = \| o_t - o_{t-1} \|$: Euclidean/metric distance between consecutive GPS fixes.
* $d_{\text{net}}(c_i, c_j)$: Shortest directed distance through the road graph from arc $c_i$ to arc $c_j$.

$$P(s_t = c_j \mid s_{t-1} = c_i) = \frac{1}{\beta} \exp\left( - \frac{|d_{\text{net}} - d_{\text{obs}}|}{\beta} \right)$$
In log-space:
$$\log P(s_t = c_j \mid s_{t-1} = c_i) = -\log \beta - \frac{|d_{\text{net}} - d_{\text{obs}}|}{\beta}$$

### Edge Cases Handled:
1. **Same Arc ($c_i == c_j$)**: $d_{\text{net}} \approx d_{\text{obs}} \implies |d_{\text{net}} - d_{\text{obs}}| \approx 0$ (high transition probability).
2. **Direct Connection ($\text{to\_node}(c_i) == \text{from\_node}(c_j)$)**: $d_{\text{net}} = \frac{\text{len}(c_i) + \text{len}(c_j)}{2}$.
3. **Multi-Hop Traversal**: Dijkstra shortest path in directed graph:
   $$d_{\text{net}} = \text{dist}_G(\text{to\_node}(c_i), \text{from\_node}(c_j)) + \frac{\text{len}(c_i) + \text{len}(c_j)}{2}$$
4. **Disconnected / Unreachable Roads**: $d_{\text{net}} = \infty \implies \log P = -100.0$ (strongly penalized; avoids crashing the Viterbi trellis).
5. **Large Time Gaps ($\Delta t > 60$s)**: $\beta$ is scaled by $(1 + \log_{10}(\Delta t / 60))$.

---

## 8. Why is Road Network Connectivity Important?

A road network is a **directed multigraph** $G = (V, E)$. Roads have one-way restrictions, turn prohibitions, and dual carriageways.
* Without directed connectivity, map matching can select roads in the reverse direction of traffic or cross uncrossable barriers.
* Using NetworkX Dijkstra on Member 1's directed road graph guarantees that transitions reflect legal, physically drivable vehicle paths.

---

## 9. How Does the Viterbi Algorithm Work?

The **Viterbi algorithm** is a dynamic programming algorithm that computes the maximum a posteriori (MAP) sequence of hidden states $S^* = (s_0^*, s_1^*, \dots, s_{T-1}^*)$ maximizing $P(S \mid O)$.

### Log-Space Recurrence:
1. **Initialization ($t = 0$)**:
   $$\delta_0(j) = -\log |C_0| + \log P(o_0 \mid c_{0, j})$$
2. **Recursion ($t = 1 \dots T-1$)**:
   $$\delta_t(j) = \log P(o_t \mid c_{t, j}) + \max_{i \in C_{t-1}} \left[ \delta_{t-1}(i) + \log P(c_{t, j} \mid c_{t-1, i}) \right]$$
   $$\psi_t(j) = \arg\max_{i \in C_{t-1}} \left[ \delta_{t-1}(i) + \log P(c_{t, j} \mid c_{t-1, i}) \right]$$
3. **Termination**:
   $$s_{T-1}^* = \arg\max_{j \in C_{T-1}} \delta_{T-1}(j)$$
4. **Backtracking**:
   $$s_t^* = \psi_{t+1}(s_{t+1}^*) \quad \text{for } t = T-2, T-3, \dots, 0$$

---

## 10. How is the Final Route Reconstructed?

After Viterbi selects the best candidate arc for each GPS observation:
1. **Consecutive Arc Analysis**:
   * If $a_t == a_{t+1}$: Vehicle remained on the same road arc.
   * If $\text{to\_node}(a_t) == \text{from\_node}(a_{t+1})$: Consecutive arcs are directly connected.
   * If $\text{to\_node}(a_t) \neq \text{from\_node}(a_{t+1})$: Sparse GPS sampling skipped one or more road arcs!
2. **Intermediate Arc Inference**:
   * The system runs shortest-path recovery between $\text{to\_node}(a_t)$ and $\text{from\_node}(a_{t+1})$ on the directed road graph.
   * Intermediate arcs are inserted with metadata flag `source="inferred_path"` (`is_inferred=True`), preserving full physical continuity without falsifying observation points.
3. **Route Continuity Metric**:
   $$\text{Continuity} = \frac{\text{Valid Consecutive Directed Transitions}}{\text{Total Transitions}} \in [0.0, 1.0]$$
